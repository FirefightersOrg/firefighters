## Decisions and known gaps

- Financial/prize rows are read with the signed-in admin client; `service_role` is not used to read
  those protected tables. Profiles/audit data are read only where the established test convention
  permits the required scoped evidence.
- **SAN-119:** freeze is intentionally idempotent: #89 retained the no-op after the consolation
  gate, rather than recording another freeze audit/state change.
- **SAN-123 (in progress, #93):** completed-draw refusal cannot be verified end-to-end because there
  is no public `roster_frozen -> completed` transition. C1 deliberately uses only public APIs for
  scheduled, generated, annulled and frozen states; pgTAP 042 covers the database completed-state
  guard.
- **Decided product rule (SAN-81 review decision):** a delivered prize cannot be annulled. Annulment
  has the dedicated admin-only `prize.annul` permission (although SAN-84's original acceptance
  criterion said `prize.resolve`); the service returns `55000`/409 and C3 verifies no audit/state
  write.
- **SAN-117:** extraordinary numbers are not released on draw annulment.
- **SAN-118:** `draw.annul` follow-up remains open.
- **SAN-122 (in progress, #94):** payment/delivery documents can show `—` as registering user for
  non-admin readers.
